## 2. 跨计划已固化的约定

违反这些约定会让后续计划对不上，改之前先想清楚。

- **迁移编号**：V1–V4（01）、V5（02）、V6–V7（03）、V8–V9（04）、**V10–V11 留给 05**。
- **任务类型**：`LIBRARY_SCAN`(02)、`ARCHIVE_INDEX`(04)、`PREVIEW_GENERATE` / `SPRITE_GENERATE` / `METADATA_FETCH`(05)、`TRANSCODE`(预留)。
- **JSONB 与 TEXT[] 列一律不做 JPA 映射。** 计划 03、04 的实体都只映射标量列，`metadata` / `raw_metadata` / `field_sources` / `locked_fields` / `metadata_providers` 全部留空。原因：`ddl-auto=validate` 对 Hibernate 的数组/JSON 类型映射很挑，而这些列天然适合用 `JdbcTemplate` 直读直写。**计划 05 必须沿用这个模式，不要临时改成 `@JdbcTypeCode`。**
- **批量集合操作用 `JdbcTemplate`，实体操作用 JPA。** 计划 04 的 `ImageLibraryRecalculator`（窗口函数重编页码、前缀聚合计数）与 `ImageTreeRelocator`（一条前缀替换 UPDATE 重写子树）是范例。
- **模块依赖方向**：`scan` 不依赖 `video`/`image`（靠 `LibraryContentBuilder` SPI 倒置）；`video` 与 `image` 互不依赖，只共享 `shared` 里的 `NaturalSortKey` 与 `MaterializedPath`（**复用算法，不复用模型**）。由 `ModularityTests` 强制。
- **扫描绝不删除数据**：文件消失只标记 `scanned_file.status = MISSING`，语义层一行不删。所有"回收"逻辑都必须建立在这个前提上。
- **404 而非 403**：无权访问一律抛 `NotFoundException`，不泄露资源存在性。
- **测试里跑任务**：`scanTrigger.requestScan(id)` 后调 `jobPoller.pollOnce()`；扫描会再排出下游任务（如 `ARCHIVE_INDEX`），**需要再调一次** `pollOnce()`。
- `AbstractIntegrationTest` 不带 `@Transactional`，容器在测试间共享——测试要用 `UUID` 造独立的库名与用户名。

## 4. 计划 05 的设计定稿（写计划时直接照用，不要重新推导）

### 4.1 任务切分（12 个）

1. `derived_asset` 表 + 派生资源存储布局（V10，含给 `cover_asset_id` 补外键）
2. 外部进程运行器 `CommandRunner` + ffprobe 输出解析（纯单元测试）
3. 视频预览生成：`PREVIEW_GENERATE` 处理器（探测回填 `video_file` → 抽帧封面 → 缩略图）
4. 图片预览生成：图集/漫画封面（含 CBZ 首页读取）
5. 雪碧图与 WebVTT（`SPRITE_GENERATE`）
6. 事件接线 + `GET /api/assets/{id}` 资源访问端点 + 封面写回
7. 字段合并策略（`shared`）+ 领域写回入口 + 用户编辑与字段锁定端点
8. `MetadataProvider` SPI + `LocalNfoProvider`
9. `FilenameProvider` + 提供者链编排 `MetadataResolver`
10. 外部 Provider：`BangumiProvider` + `TmdbProvider`（限流、缓存、缺 key 降级）
11. `METADATA_FETCH` 任务 + `scrape_candidate` 候选队列与确认端点 + `collection` 填充
12. 全量验证与讲解文档

### 4.2 模块依赖方向（关键，决定了整个模块设计）

```
preview  → scan, library, jobs, shared, video, image
metadata → scan, library, jobs, shared, video, image
video / image → 绝不引用 preview / metadata
```

无环，`ApplicationModules.verify()` 能过。做法是 `preview` / `metadata` **订阅** `VideoItemCreated` / `ImageNodeCreated`（spec §4.3 的事件表），并**直接调用**领域模块的公开写回 API；领域模块永远不反向引用它们。

**为什么这里不像 `scan` 那样做 SPI 倒置**（这是 ADR 素材）：物理扫描是真正与领域无关的，倒置能让"加第三个域不改扫描代码"成立；而**刮削本身就是领域特定的**（TMDB 管电影、Bangumi 管番剧与漫画），倒置只会把 if/else 换个地方摆，还多一层间接。同一个项目里两次相反的取舍，各有各的理由——比"我全都倒置了"更能说明判断力。

### 4.3 元数据优先级：两套机制各管一件事

spec §7.2 的 `用户编辑 > 本地元数据文件 > 刮削 > 文件名`，用两个既有机制表达，**不要再引入第三套 tier 比较**：

- **链的顺序表达优先级**：`LocalNfo → 各刮削器（按 `libraries.metadata_providers` 配置序） → Filename 兜底`，**命中即停**。
- **`locked_fields` 表达覆盖保护**：用户编辑过的字段写入 `locked_fields`，任何刮削不得覆盖。
- `field_sources` 只记录"这个字段是谁写的"，供界面展示，不参与判定。

`shared` 新增：`MetadataPatch(source, sourceId, fields, extras, rawResponse)`、`MetadataFields`（标准字段名常量）、`FieldMergePolicy`（跳过 `locked_fields`、跳过空值，约 20 行 + 单元测试）。

写回入口（本计划新增到既有模块，属于 Modify）：
- `VideoCatalogService.applyMetadata(itemId, MetadataPatch)` / `applyUserEdit(...)` / `assignCover(itemId, assetId)`
- `ImageCatalogService.applyMetadata(nodeId, MetadataPatch)` / `applyUserEdit(...)` / `assignCover(nodeId, assetId)`
- `ImageCatalogService.openPageForProcessing(fileId)` —— **不做权限校验**，仅供后台任务取首页生成封面，javadoc 必须写明
- `LibraryService.metadataProvidersOf(libraryId)` / `setMetadataProviders(...)` —— 走 `JdbcTemplate` 读写 `text[]`
- 各域的 `*MetadataStore`（package-private，`JdbcTemplate`）读写 `metadata` / `raw_metadata` / `field_sources` / `locked_fields`

`image_node` 没有 `release_date` / `rating` 列，这两个标准字段对图片域落进 `metadata` jsonb。

### 4.4 派生资源

- `derived_asset(id, kind, source_scanned_file_id, relative_path, width, height, size_bytes, generated_at)`，`UNIQUE (source_scanned_file_id, kind)`。
- 存储根由 `mymedia.preview.root` 配置（默认 `./data/derived`），路径两级分片（`covers/{id % 100}/{id}-cover.jpg`），避免单目录堆几十万文件。
- **`cover_asset_id` 的外键在 V10 才加**（`ON DELETE SET NULL`）：V6 / V8 建表时 `derived_asset` 还不存在，所以只有列没有约束。这个顺序本身就是一个讲得清的点。
- 派生目录删光后可由任务队列全量重建，不碰任何用户数据（spec §6.2 的承诺）。

### 4.5 ffmpeg / ffprobe

烘焙进应用镜像，**不要求本机安装**，因此：

- 所有解析逻辑（ffprobe JSON → `video_file` 字段）是**纯单元测试**，喂 fixture 字符串。
- 进程调用走可注入的 `CommandRunner`（`run(List<String> command, Duration timeout) → CommandResult(exitCode, stdout, stderr)`）。
- 任务处理器的集成测试用 Spring `@TestConfiguration` + `@Primary` 提供**桩 runner**（按命令行末尾的输出路径写几个假字节），**不要用 Mockito**——计划 01 把 Boot 4 的 test starter 拆开引了，Mockito 是否在 classpath 上没有验证过。
- 真机调用只保留一个带 `assumeTrue(ffprobe 可用)` 的测试。

命令：

| 用途 | 命令 |
|---|---|
| 探测 | `ffprobe -v quiet -print_format json -show_format -show_streams <file>` |
| 封面 | `ffmpeg -y -ss <duration*0.1> -i <file> -frames:v 1 -vf scale=640:-2 -q:v 3 <out.jpg>`（`-ss` 放 `-i` 前是快速定位） |
| 缩略图 | 不再解一次视频，用 ImageIO 从封面缩到 320 宽 |
| 雪碧图 | `ffmpeg -y -i <file> -vf fps=<100/duration>,scale=160:-2,tile=10x10 -frames:v 1 <out.jpg>` |

**雪碧图固定 100 帧、单张 10×10**，间隔按时长算。这样永远只有一张图、一个 VTT，省掉多图分页的全部复杂度。VTT 在 Java 里按几何关系生成。

探测必须先于抽帧：不知道时长就选不出抽帧点，所以两者在同一个 `PREVIEW_GENERATE` 处理器里顺序执行（spec 的 job type 清单里本来也没有单独的 PROBE 类型）。

### 4.6 刮削

- `MetadataProvider`（public SPI）：`name()`、`supports(LibraryDomain)`、`search(ScrapeSubject) → List<MetadataCandidate>`、`fetch(subject, candidate) → Optional<MetadataPatch>`。
- 置信度：`TitleSimilarity` 用**字符二元组 Dice 系数**（对中文有效，和 `pg_trgm` 的三元组正好是一组可对照的讲解素材）。高分（≥0.8）自动应用 → `MATCHED`；中分（0.4–0.8）写 `scrape_candidate` → `NEEDS_REVIEW`；无候选 → 回落 `FilenameProvider` 并置 `NO_MATCH`（**安静回落，界面不显示为错误**）；网络故障/限流才置 `ERROR` 并重试。
- `libraries.metadata_providers` 为空数组 → 该库条目 `scrape_status = NOT_APPLICABLE`，**根本不排任务**。
- 外部 Provider 必须带标识性 `User-Agent`、客户端侧限流、结果缓存（用 Spring 自带的 `ConcurrentMapCacheManager`，**不引 Redis 也不引 Caffeine**）。
- TMDB 缺 API key 时优雅降级：Provider 直接报告不可用，链跳过它，不算错误。
- **Provider 测试用 JDK 的 `com.sun.net.httpserver.HttpServer` 起本地桩**（已验证可用），不引 MockWebServer，也不赌 `MockRestServiceServer` 对 `RestClient` 的支持。
- `collection` 填充：`MetadataPatch.extras` 带 `collection` 键时，`video` 侧 find-or-create 同库的 `collection` 行并挂上条目（计划 03 只建了表没填）。
