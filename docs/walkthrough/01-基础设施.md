# 01：基础设施阶段讲解

本文面向项目所有者，解释 MyMedia 第一阶段交付的四个模块、数据库约束、认证和持久化任务队列。可以先运行 `docker compose up -d` 和 `mvn -B -ntp verify`，再结合 `target/spring-modulith-docs/` 下的 Modulith 文档阅读。

## 1. Spring Modulith 到底做了什么？

Spring Modulith 把顶层 Java 包当作模块：`com.mymedia.user`、`com.mymedia.library`、`com.mymedia.jobs` 和 `com.mymedia.shared` 分别是独立边界。各模块的 `package-info.java` 用 `@ApplicationModule` 声明模块名称；模块需要被其他模块使用的类型才做成 `public`，实现类、repository 和构造器则保持 package-private。这样“包即模块”不是目录命名习惯，而是可以被框架分析的依赖图。当前生成的 `components.puml` 也正是从这张图导出的，而不是手工维护的架构图。

`ApplicationModules.of(MyMediaApplication.class).verify()` 会在模块依赖违反规则时失败，例如 `library` 当前可以调用公开的 `UserQueryService`，但如果 `LibraryController` 直接 import package-private 的 `UserAccountRepository`，或者 `jobs` 直接依赖 `library` 的内部实现，Modulith 就会报告越界依赖。测试入口在 `src/test/java/com/mymedia/ModularityTests.java:9-19`；模块声明在 `src/main/java/com/mymedia/user/package-info.java:1-2`、`library/package-info.java:1-2` 和 `jobs/package-info.java:1-2`。因此重构时，先看模块公开 API，而不是把任意类改成 `public`。

## 2. 为什么域分区要用复合外键？

`libraries.domain` 是视频域和图片域的数据库分区锚点。单表 `CHECK` 只能检查当前行，例如 `libraries` 的 `CHECK (domain IN ('VIDEO', 'IMAGE'))` 能保证值合法，却不能读取另一张表判断“这个 video item 的 domain 是否等于它所属 library 的 domain”。如果只在应用层检查，漏掉一个写入口或有人直接连数据库，就可能把视频条目写进图片库。

因此 `V3__libraries.sql:13-17` 先建立 `UNIQUE (id, domain)`，再让子表以 `(library_id, domain)` 引用它，并配合子表上的固定域 `CHECK`。这个唯一键不是业务上额外需要的查询索引，而是 PostgreSQL 允许复合外键引用的唯一锚点；没有它，外键目标列不满足唯一性要求，约束无法创建。完整取舍记录在 `docs/adr/ADR-001-域分区的数据库级强制.md:9-24`；内部设计规格里还有一段通用写法，该文档未随仓库发布。

## 3. `FOR UPDATE SKIP LOCKED` 是怎么工作的？

`src/main/java/com/mymedia/jobs/JobRepository.java:33-40` 用 `status = 'PENDING'`、优先级和计划时间挑选任务，然后用 `FOR UPDATE SKIP LOCKED` 锁住选中的行。多个 worker 同时执行时，已经被第一个 worker 锁住的行会被第二个 worker 跳过，而不是让第二个 worker 等待；所以每个 worker 能拿到互不相交的任务集合。行锁是数据库级并发协调，不需要 Redis 或消息队列。

抢占和状态更新必须在同一个事务里。`JobClaimService.claim` 在 `src/main/java/com/mymedia/jobs/JobClaimService.java:28-46` 使用 `REQUIRES_NEW` 事务，先查询并加锁，再立即把任务标成 `RUNNING` 并写入租约。如果把查询和状态更新拆成两个事务，第一个事务结束时行锁释放，另一个 worker 就能在状态仍是 `PENDING` 的窗口中拿到同一任务，最终产生重复执行。这个选择的系统级理由见 `docs/adr/ADR-003-用数据库任务表替代消息队列.md:9-30`。

## 4. 租约解决的是什么问题？

worker 进程可能在任务已经被抢占后崩溃：数据库只知道任务曾被标成 `RUNNING`，并不知道承载它的 JVM 是否还活着。如果没有额外机制，这个任务就会永久卡在 `RUNNING`，既不会重试也不会被别的 worker 执行。`V4__jobs.sql:14-15` 为任务保存 `lease_owner` 和 `lease_expires_at`，抢占时由 `JobClaimService.java:39-45` 写入 owner 与过期时间。

超时是这里唯一可靠的探测手段。进程崩溃时无法再发送“我死了”的消息，数据库也不能直接观察操作系统进程；其他 worker 只能在 `lease_expires_at` 到达后把它当成失联并回收。`JobRepository.java:42-52` 将过期的 `RUNNING` 任务退回 `PENDING`，而 `JobClaimService.java:49-58` 负责在事务中触发回收。租约时间越短，故障恢复越快但越容易误判慢任务；当前配置在 `src/main/resources/application.yml:35-38` 使用 10 分钟，适合阶段性后台任务。

## 5. 为什么无权访问的媒体库返回 404 而不是 403？

对一个没有权限的用户返回 `403 Forbidden`，等于告诉他“这个 id 对应的资源确实存在，只是你不能看”。攻击者可以遍历 id，借此枚举媒体库名称、数量或组织结构。返回 `404 Not Found` 把“资源不存在”和“资源存在但当前用户不可见”合并成同一个外部结果，避免泄露资源存在性。

实现位于 `src/main/java/com/mymedia/library/LibraryController.java:45-53`：先由 `LibraryAccessService.canAccess` 判断权限，失败就抛出 `NotFoundException`，而不是抛出权限异常。管理员隐式拥有所有媒体库、普通用户只读取 `library_access` 授权，见 `src/main/java/com/mymedia/library/LibraryAccessService.java:27-36` 和 `53-66`。回归测试 `src/test/java/com/mymedia/library/LibraryControllerTest.java:88-97` 明确守住了这个 404 语义。

## 6. `@PreAuthorize` 为什么需要 `@EnableMethodSecurity`？

`@PreAuthorize` 是方法级授权注解，不是 HTTP 路由匹配规则。`LibraryController.create` 在 `src/main/java/com/mymedia/library/LibraryController.java:56-63` 上要求 `hasRole('ADMIN')`，但只有在 Spring Security 开启 method security 后，Spring 才会为这个方法建立拦截器。`SecurityConfig.java:13-16` 的 `@EnableMethodSecurity` 就是这个开关；如果漏掉它，应用仍然能启动、登录也仍然成功，但注解可能静默不生效，普通用户就可能调用管理员写接口。

`SecurityConfig.java:18-28` 的 HTTP 配置只负责健康检查公开、其他请求必须认证和启用 HTTP Basic，并不能替代角色检查。测试 `src/test/java/com/mymedia/library/LibraryControllerTest.java:60-72` 用普通用户调用创建媒体库并断言 `403`，因此同时验证了注解存在和 `@EnableMethodSecurity` 真正生效。这是一个容易在手工登录测试中漏掉、但影响权限边界的静默失效点。

## 7. 初始管理员是如何引导的？

`src/main/java/com/mymedia/user/AdminBootstrap.java:9-34` 是 user 模块内的 package-private 配置类。应用启动时，`ApplicationRunner` 读取 `mymedia.admin.username` 与 `mymedia.admin.password`，先通过 package-private 的 `UserAccountRepository.existsByUsername` 查重，只有不存在时才调用 `UserRegistrationService.register(..., UserRole.ADMIN)`。注册服务会在 `src/main/java/com/mymedia/user/UserRegistrationService.java:18-25` 中用 `PasswordEncoder` 保存哈希，因此不会把明文密码写进 `users` 表。

`src/main/resources/application.yml:31-37` 提供本地演示用的 `admin/admin` 默认值；部署时可以用 `MYMEDIA_ADMIN_USERNAME` 和 `MYMEDIA_ADMIN_PASSWORD` 覆盖。查重分支使重启不会重复插入账号，日志也明确提醒第一次启动后应立即修改默认密码。该类不公开 repository，符合 user 模块“只暴露必要公开类型”的边界。

## 8. 如何复现和验证这一阶段？

先执行 `docker compose up -d`，确认 `mymedia-postgres` 是健康状态，再执行 `mvn -B -ntp verify`。集成测试的 `src/test/java/com/mymedia/AbstractIntegrationTest.java:11-23` 使用 Testcontainers 的 `postgres:17`，所以迁移、JPA、`pg_trgm` 和任务队列测试不是 H2 近似验证。Modulith 的 `ModularityTests` 还会将模块图和模块说明写入 `target/spring-modulith-docs/`。

应用启动后，`GET /actuator/health` 应返回 `status=UP`；未认证访问 `GET /api/libraries` 应为 `401`；默认管理员认证后，列表初始为空，创建 VIDEO 媒体库应为 `201`。`src/test/java/com/mymedia/user/AuthenticationTest.java:41-62` 还覆盖匿名、正确凭证、默认管理员和错误密码四条认证路径。
